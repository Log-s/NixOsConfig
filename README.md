# NixOS Config

Personal NixOS flake configuration. Niri window manager, Noctalia shell, home-manager for dotfiles.

## Applying to an existing NixOS install (graphical installer)

If you installed NixOS via the graphical installer rather than directly from the flake, use this
workflow after the first boot.

### 1. Clone the repo

```bash
nix-shell -p git
git clone git@github.com:Log-s/NixOsConfig.git ~/NixOsConfig
```

### 2. Update hardware.nix with your actual partition UUIDs

The graphical installer generated a hardware config for your machine at `/etc/nixos/`. Use it to
update `hardware.nix` in the repo:

```bash
cat /etc/nixos/hardware-configuration.nix
# note the UUID(s) for fileSystems."/" (and /boot if present)
```

Edit `~/NixOsConfig/modules/hosts/main/hardware.nix` and replace the UUID(s) to match. Also check
that the bootloader settings match your partition layout (GRUB device, EFI mount point, etc.).

### 3. Switch to the flake config

```bash
cd ~/NixOsConfig
sudo nixos-rebuild switch --flake .#main
```

Nix will build the full system from the flake and activate it. Home-manager runs as part of the
same build and deploys all dotfiles. Log out and back in (or reboot) to pick up the new shell,
niri session, and noctalia.

### 4. Post-install steps (manual, one-time)

These cannot be automated via Nix:
- Switch color scheme once in Noctalia → triggers theme writes for all templates (Alacritty, Vesktop, …)
- Run `qt6ct` → select the Noctalia color scheme
- Vesktop:
  1. Login
  2. Switch Noctalia themes to force a write
  3. Vesktop Settings → Themes → select the Noctalia theme
- Firefox → pywalfox extension → "Fetch Pywal colors"
- Obsidian: launch, open `~/.obsidian/Vaults` as vault, configure plugins manually

## Day-to-day commands

```bash
# Rebuild and switch (run from ~/NixOsConfig on the target machine)
sudo nixos-rebuild switch --flake .#main

# Build without switching (check for errors)
sudo nixos-rebuild build --flake .#main

# Show full error trace
sudo nixos-rebuild switch --flake .#main --show-trace

# Update all flake inputs
nix flake update

# List and delete old generations
nixos-rebuild list-generations # list
sudo nix-collect-garbage -d # remove all old generations
sudo nix-collect-garbage  --delete-generations 1 2 3 # remove specific generations
sudo nixos-rebuild switch --flake .#main # remove entries from boot menu
```

## Architecture

### Module loading

`flake.nix` delegates everything to `flake-parts` and uses `import-tree` to auto-load **every
`.nix` file under `modules/`** as a flake-parts module. Adding a file to `modules/` is enough for
it to be picked up — there is no manual imports list in `flake.nix`.

Each file in `modules/` must be a valid flake-parts module (top-level function receiving
`{ self, inputs, ... }`). They expose outputs via `flake.nixosModules.*`,
`flake.nixosConfigurations.*`, or `perSystem`.

### Two-layer structure

`modules/` contains system-level NixOS config. `home/` contains user-level dotfiles managed by
home-manager. They are kept separate because import-tree would try to load home-manager modules as
flake-parts modules (and fail). The home config is wired in explicitly from
`modules/hosts/main/default.nix`.

### How a feature gets activated

1. A feature file (e.g. `modules/features/packages.nix`) defines
   `flake.nixosModules.packages = { pkgs, ... }: { ... }`.
2. `modules/hosts/main/configuration.nix` lists it in `imports = [ self.nixosModules.packages … ]`.
3. `modules/hosts/main/default.nix` builds the final `nixosSystem` and wires in home-manager.

### Niri + Noctalia (wrapper-modules pattern)

Niri is built via `inputs.wrapper-modules.wrappers.niri.wrap` in `modules/features/niri.nix`,
producing `packages.myNiri`. Settings are expressed as a Nix attrset — wrapper-modules converts
them to KDL at build time.

Noctalia is exposed as `packages.myNoctalia` from `inputs.noctalia.packages.*`. Both packages are
referenced by name inside niri's `spawn-at-startup` configuration.

An activation script in `modules/features/niri.nix` writes a processed copy of the generated
`niri-config.kdl` to `~/.config/niri/config.kdl` so tools that read the user config can parse it
(the raw KDL uses quoted identifiers that most parsers do not understand).

Noctalia is driven from niri keybinds through its CLI: `noctalia msg <command>` (v5) — for example
`msg panel-toggle launcher`, `msg settings-toggle`, `msg window-switcher`, `msg lock`.

### Noctalia theming

Noctalia centrally themes most apps via its template system. Active templates are listed in
`modules/features/noctalia/config.toml` under `[theme.templates]`: `builtin_ids` for templates
shipped with noctalia, `community_ids` for ones fetched from the community catalog and cached in
`~/.local/state/noctalia/community-templates`. Run `noctalia theme --list-templates` to see both
catalogs.

The palette itself comes from the wallpaper (`[theme] source = "wallpaper"`, `mode = "dark"`), so
changing the wallpaper re-renders every active template. Apps that follow automatically:

- **Alacritty** — writes `~/.config/alacritty/themes/noctalia.toml`
- **GTK 3 / GTK 4** — adw-gtk3-dark theme + the gtk3/gtk4 templates
- **Qt / btop / niri** — built-in templates
- **Helix** — built-in template writes `~/.config/helix/themes/noctalia.toml` (`programs.helix`
  selects it by name)
- **Vesktop** — the `discord` community template writes `~/.config/vesktop/themes/noctalia.theme.css`
  (enable it once in Vesktop's Themes pane)
- **Obsidian** — the `obsidian` community template writes a `noctalia` CSS snippet into each vault
- **Firefox** — the `pywalfox` community template writes `~/.cache/wal/colors.json` and runs
  `pywalfox update`

Not wallpaper-driven:

- **Spotify** — spicetify-nix bakes `colors.css` into the read-only store at build time, so the
  `spicetify` community template's output in `~/.config/spicetify/` is never read. Change
  `colorScheme` in `home/log_s/spicetify.nix` and rebuild instead.
- **VSCodium** — themed by extension (Catppuccin)


### Flake inputs

| Input | Purpose |
|-------|---------|
| `nixpkgs` | Main package set (nixos-unstable) |
| `flake-parts` | Flake output organization |
| `import-tree` | Auto-loads all `.nix` files under `modules/` |
| `wrapper-modules` | Builds niri with settings baked in at compile time |
| `home-manager` | User-level dotfile management |
| `noctalia` | Official noctalia v5 shell flake (binary cache: noctalia.cachix.org; nixpkgs deliberately not followed so cache hits are preserved) |
| `spicetify-nix` | Spotify theming (patches Spotify at build time) |
| `nur` | Nix User Repository — used for Firefox extensions (rycee's firefox-addons) |
| `nix-vscode-extensions` | Full Open VSX + VS Code Marketplace mirror for VSCode extensions |
